# QA — Document Creation

## 1. Критерии приёмки

### AC-01. Создание Invoice

**Позитивный тест:** Пользователь с правом создания документов выбирает тип `Invoice`, заполняет обязательные поля и сохраняет документ. Система создаёт документ типа `Invoice`.

**Негативный тест:** Пользователь пытается сохранить `Invoice` без обязательного поля. Система не создаёт документ и отображает сообщение об ошибке. Точный текст сообщения необходимо уточнить.

---

### AC-02. Создание Tax Document

**Позитивный тест:** Пользователь выбирает тип `Tax Document`, заполняет обязательные поля и сохраняет документ. Система создаёт документ типа `Tax Document`.

**Негативный тест:** Пользователь пытается сохранить `Tax Document` без обязательного поля. Система не создаёт документ и отображает сообщение об ошибке. Точный текст сообщения необходимо уточнить.

---

### AC-03. Создание Proforma

**Позитивный тест:** Пользователь выбирает тип `Proforma`, заполняет обязательные поля и сохраняет документ. Система создаёт документ типа `Proforma`.

**Негативный тест:** Пользователь пытается сохранить `Proforma` без обязательного поля. Система не создаёт документ и отображает сообщение об ошибке. Точный текст сообщения необходимо уточнить.

---

### AC-04. Данные компании берутся из профиля

**Позитивный тест:** В профиле компании указаны `Company name = Test Company`, `Country = Germany`, `Tax ID = DE123456789`. При создании документа система автоматически подставляет эти значения из профиля компании.

**Негативный тест:** В профиле компании отсутствует обязательное поле. При создании документа система не должна сохранять документ с неполными данными и должна показать сообщение об ошибке. Точный текст сообщения необходимо уточнить.

---

### AC-05. Автоматический расчёт суммы

**Позитивный тест:** При `Quantity = 2` и `Unit price = 100 EUR` система автоматически рассчитывает `Subtotal = 200 EUR`.

**Негативный тест:** Пользователь вводит отрицательное значение `Quantity = -1`. Система не принимает значение и отображает сообщение об ошибке. Точный текст сообщения необходимо уточнить.

---

### AC-06. Автоматический расчёт VAT

**Позитивный тест:** При `Subtotal = 200 EUR` и ставке VAT `20%` система автоматически рассчитывает `VAT = 40 EUR`.

**Негативный тест:** Для выбранной страны отсутствует настроенное правило VAT. Система не применяет произвольную ставку и отображает сообщение об ошибке.

---

### AC-07. Расчёт итоговой суммы

**Позитивный тест:** При `Subtotal = 200 EUR` и `VAT = 40 EUR` система отображает `Total = 240 EUR`.

**Негативный тест:** Пользователь изменяет `Quantity` с `2` на `3`. Система пересчитывает `Subtotal`, `VAT` и `Total`; старые значения не остаются отображаться.

---

### AC-08. Сохранение черновика

**Позитивный тест:** Пользователь заполняет форму документа и нажимает `Save Draft`. Система сохраняет документ со статусом `Draft`.

**Негативный тест:** Пользователь пытается сохранить Draft без обязательного поля. Система не сохраняет документ и отображает сообщение об ошибке.

---

### AC-09. Повторное открытие черновика

**Позитивный тест:** Пользователь сохраняет документ со статусом `Draft`, закрывает его и открывает повторно. Все ранее сохранённые значения отображаются без изменений.

**Негативный тест:** Пользователь открывает сохранённый Draft после изменения данных. Система не должна самопроизвольно изменять сохранённые значения.

---

### AC-10. Отправка документа клиенту

**Позитивный тест:** Пользователь отправляет созданный документ клиенту. При успешной отправке система отображает сообщение `Document sent successfully.`

**Негативный тест:** Отправка документа завершается ошибкой. Система не отображает сообщение об успешной отправке и показывает сообщение `Failed to send document.`.

## 3. Что нужно для проверки

### Пользователь

Тестовый пользователь с правами на:

- создание документов;
- сохранение Draft;
- отправку документов клиенту.

### Компания

Тестовая компания с заполненным профилем:

- `Company name`;
- `Address`;
- `Country`;
- `Tax ID`;

### Клиент

Тестовый клиент с:

- именем;
- необходимыми контактными данными;
- email, если отправка выполняется по email.

### Данные для расчётов

Для проверки автоматического расчёта:

- `Product/Service = Test Service`;
- `Quantity = 2`;
- `Unit price = 100 EUR`;
- `VAT — согласно правилам выбранной страны`.

### Что должно быть в системе до начала тестирования

1. Создан тестовый пользователь.
2. Создана тестовая компания.
3. Заполнен профиль компании.
4. Создан тестовый клиент.
5. Настроены правила VAT для тестируемой страны.
6. Есть данные для создания документа.
7. Доступна отправка документа клиенту.
